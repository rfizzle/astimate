# Report field reading: `astimate report` on eleven repositories

Read on 2026-10-15 against the report design of 2026-10-14 (`docs/design/report-design-2026-10-14.md`), with astimate at cdc81c7 plus the sentence fixes this note records, and the embedded default configuration (`thresholds-2026-10-14b`; no `astimate.yaml` in the working directory). Read by an Opus subagent; not reviewed line by line by a person.

## Method

Each sibling repository was read in place, read-only, from a scratch directory: `astimate report <repo>` as a 120-column terminal (`--color never`, through a pseudo-terminal so the width applies), `--format json`, `--format html --out`, and with `--base HEAD~30` the change page, the Markdown and the change text (`--base HEAD~8` on goKMS, which has 9 commits). `git worktree list` showed only the main checkout of every repository after the runs. Every verdict, lead, "Start here" card, story, "do this", rebuild, copies and complexity sentence, and every finding's why, what to do and place to open, was read against the numbers on its own row and against the code: each longest repeat's two ranges were opened and compared, each hardest function's `file:line` was checked to declare that function, each finding's file was checked to exist with the line inside it, and the cited code was read where a sentence made a claim about it (the repeats in goKMS `internal/kms`, mark `renderer` and kubesentry `internal/convert`, the changed functions of mark and crush, the opened lines of overwatch's findings). The first run used cdc81c7 as shipped; the fixes below were made, and every repository was run again to read the changed sentences in place.

## The three decisions

1. **The terminal change report printed `cmp.Or(Why, Do)`, so a `globals` or `untested_exports` finding lost the names its suggestion carried.** Both are printed now, the why sentence then the suggestion's first clause (capitalized), as the HTML page already did; the names (`joins`, `JoinAgain` in the fixture) are what a reader opens the file for. Moving the names into the why would make the why a second copy of the suggestion for every rule that has one. The cost is a longer finding where the suggestion repeats the moved column ("Grew 330 while over the 600 ceiling …" beside "grew 330, allowed 50"); at 80 columns or fewer the why line is still left out.
2. **`why("sloc")` said "was already past" of a change that crossed the ceiling.** It is now worded for both cases as the `tokens_est` sentence is: "The package is past what one agent pass can hold, and this change took it there or grew it more than one change is allowed to." Three of the eleven change reports had a crossing (ztp, mark, crush).
3. **On a module without churn, fine packages appeared under "Start here" with "Nothing. Leave it alone."** The field run showed it is not only a no-churn problem: with churn, fine packages ranked high enough to be listed on goKMS, ai-orchestration (two of three), go-starter, mark, ai-shell (two of three), zero-trust-proxy (two of three) and ztp (all three, while the headline said two packages needed a split). So `hotspots` now holds only split and watch packages, ranked by hotspot score as before, which without churn is rebuild days alone, and a module of fine packages has no "Start here". Ranking every package by rebuild days with a sentence saying churn was unavailable was rejected: it keeps the contradiction of a card that says to start on a package and to leave it alone. Without churn the lead says "There is no change history to read, so the packages to start with are ranked by rebuild time alone.", the HTML note drops the changes clause, and the terminal heading already says "by days to rebuild". `report_module` reads `hotspots`, `headline` and `lead`, so it agrees with every renderer; its golden on the fixture (a module without churn) now lists the one watched package, `dupes`, instead of three fine ones.

## Read and true

- Bands against their numbers: every package's band matches its tier, ceilings over and copied share on all eleven repositories.
- Hardest functions: every `file:line` declares the named function (mark `ConfluenceLinkRenderer.renderLink` at `renderer/link.go:29`, crush `UI.Update` at `internal/ui/model/ui.go:706`, overwatch `ValidateParams` at `internal/modules/analysis/scoring/params.go:662`), except a TypeScript arrow function one line below its `const` (follow-up).
- Finding locations: every file exists with the line inside it; a changed-function finding opens on the function, a duplicate on an occurrence, a size finding on the largest file.
- Rebuild, sittings and human time agree with the row (7.8 passes is "about 8 sittings", 328 days "1 engineer-year", shown as `1.5 yr` in the table).
- The remaining longest repeats were opened where line similarity was low: they are the same block with renamed identifiers (kubesentry `internal/convert`, `EntitiesToSchema` against `RolesToSchema`) or the same shape of declarative lines (go-starter `cmd/serve.go`'s flag definitions, mark `stdlib.go`'s template lines, overwatch's SQL strings), which the copies view counts as tables and boilerplate.

- The change counts line and the `<module>` finding give two heads for cross-package copies (ztp `45 → 40` and `45 → 51`; zero-trust-proxy `4 → 9` and `4 → 5`): the line is the module's whole count at `min_tokens`, the finding the gate's baseline plus the blocks added at `min_tokens_cross` (`internal/engine/internal/judge/cross.go` `gated`, `internal/narrate/compose/build.go` `Cross`).

- `has_tests` findings print `0 → 0` and `require true` for a boolean.
- The change report lists every deleted package on one wrapped line: go-starter's `HEAD~30` change, which stopped vendoring, printed several hundred `vendor/...` paths.
- A TypeScript `export const f = (...) =>` is located on the arrow's line, one below the name (ai-shell `src/helpers/completion.ts:190` for `readData`).
- The headline's "Start with" follows `hotspots`, so a module whose hottest package is watched (zero-trust-proxy) names none in the headline; a sentence naming the split package to start with would need its own rule.
